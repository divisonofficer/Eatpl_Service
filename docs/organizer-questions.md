# 주최 측(BC카드 AI 사업팀) 확인 요청 — 회식픽

> 문의처: bcaimerchant@bccard.com (제휴), nykim@bccard.com (API)
> 서비스: 회식픽 — 회식 장소를 지도에서 고르고 단톡방 안내문을 만드는 웹 서비스. k-skill `bccard-eatpl-search` 사용.

## 1. 순 사용자 집계 방식

1. **iframe 모달 집계 여부**
   매장 카드에서 "잇플에서 상세 보기"를 누르면, k-skill로 받은 `merUrl`을 **변형 없이** 회식픽 페이지 위 모달의 iframe으로 띄웁니다
   (같은 화면에 "새 창으로 열기" 링크도 항상 제공). 이 경우도 순 사용자로 집계되나요?
   iframe 안에서는 제3자 쿠키가 막힐 수 있어, 집계가 안 된다면 새 창 열기만 쓰겠습니다.

2. **후보 공유 페이지**
   사용자가 고른 후보 1~3곳을 단톡방에 공유할 때, `merUrl` 대신 **회식픽 페이지 링크**(`https://<도메인>/?share=...`)를 보냅니다.
   받은 사람은 회식픽에서 지도와 카드를 보고 각 매장의 잇플 상세로 이동합니다.
   이 페이지가 안내문의 "단축 URL·중간 페이지로 감싸 연결"에 해당하나요? (리다이렉트 없이 사용자가 직접 클릭하는 일반 페이지입니다.)

3. **카카오톡 인앱 브라우저**
   단톡방에서 링크를 열면 대부분 카카오톡 인앱 브라우저입니다.
   (a) 인앱 브라우저에서 회식픽 → 잇플로 이동한 경우 집계되나요?
   (b) 안 된다면, `kakaotalk://web/openExternal` 스킴으로 기본 브라우저 열기를 안내해도 되나요?

4. **등록 도메인**
   등록 호스트명은 1개만 가능한가요? (예: `hoesikpick.vercel.app`, 이후 자체 도메인으로 변경 가능 여부)

## 2. 데이터 활용 범위

5. **상세 페이지 정보의 API 제공**
   `merUrl` 상세 페이지에 있는 아래 정보가 회식 장소 추천에 핵심인데, API 필드로 받거나 화면에 써도 되나요?
   - 회식 추천 등급 (예: "회식: 추천, 인기 많음") — API의 `empyVsitYn`(boolean)보다 세밀함
   - 요일별·시간대별 매출 비율 (예: 21:00–24:00 49.05%)
   - 함께 방문한 가맹점 / 단골 고객이 방문한 가맹점
   - 현지 고객 비율
   현재는 상세 페이지를 **수집하지 않고**, 사용자가 잇플에서 직접 보도록 안내만 합니다.

6. **결과 캐싱**
   k-skill 호출량(분당 60회)을 줄이기 위해, 같은 지역·업종 검색 결과를 서버에 수 시간 캐시해도 되나요?
   (데이터가 최근 1개월 집계라 실시간성이 크지 않음. 대량 수집·DB 구축은 하지 않습니다.)

7. **키워드 검색(GET)** — 정의서상 "파트너 개방 가능"인 `회식`·`퇴근후한잔`·`심야` 키워드 검색을 k-skill로 쓸 수 있게 열어주실 수 있나요?

## 3. 표기

8. 출처 표기 "eat.pl 잇플 · BC카드 결제 데이터 기반"을 지도 하단·목록 하단에 상시 노출합니다. 위치·문구 요구 사항이 더 있나요?

## 참고 — 데이터 품질 제보

- 일부 상세 페이지의 메뉴·AI 요약이 업종과 맞지 않습니다
  (예: 이자카야 매장 `nUGDZ2N2OPUl5Tu34TaLTA` 의 메뉴가 비빔밥·된장찌개·불고기).
- 응답 `merTpbuzNm`에 정의서 부록에 없는 값이 옵니다 (예: `바(bar)`, `호프`, `횟집`, `백반/한정식`, `유흥주점`, `주류판매점`).
